s3log

A command queue and an effect log for one database, stored as objects in one S3 bucket. No server, no locks, no retries: just conditional PUTs, GETs and LISTs.

Left / right arrow keys also step.

    cmd/<name>One command. <name> is a UUIDv7: unique, and its text order is time order.Once, by its writer, with If-None-Match: *. Never retried.
    watermarkA command name. Producers list commands only up to it.By producers, with compare-and-set (If-Match: <etag>), to the UUIDv7 bound for now − lag. Never goes down.
    fx/<n>Effect n = 1, 2, 3, …: last (the greatest command name it covers) and the commands it ran, in name order, with their results.By producers, with If-None-Match: *. The first PUT of fx/<n> wins; the others get 412.

    Effect keys. n in base62 (0-9A-Za-z), prefixed by a letter for the digit count (a = 1 digit). So 1 → a1, 10 → aA, 61 → az, 62 → b10, 3843 → bzz, 3844 → c100. Key order is numeric order.

    The watermark bound. The UUID with timestamp t ms and all other bits zero. It sorts above every UUIDv7 from before t and below every one from t on.

    Writer: submit a command

    1. Pick a fresh UUIDv7 name. PUT cmd/<name> with If-None-Match: *. Any error: unknown. No retry.
    2. GET watermark. If name > watermark: acked, it will run. Otherwise unknown: it may or may not run; its outcome will say.

    Reader

    1. GET fx/<next> until 404. Apply each effect: re-execute its commands in order; the results must match.
    2. A command's outcome: ran, with its result, if an effect contains it. dead if an effect's last passed its name without it. Every name ≤ the latest last is decided.

    Producer cycle (any number run it at once)

    1. Catch up: GET fx/<next> until 404, applying each effect.
    2. Raise the watermark to now − lag by compare-and-set, and use the value written. If the raise fails or isn't needed, GET it.
    3. LIST cmd/ starting after the latest effect's last, in key order. Stop at names above the watermark just read, or at the batch cap.
    4. Nothing listed: wait, repeat. Else GET each command and execute them in name order.
    5. PUT fx/<next> with If-None-Match: *, last = the last name listed. Success: it is canonical. 412: another producer won; discard own work, GET and apply theirs. (On any other error, GET it: the object, if present, decides; if absent, PUT again.)

    Guarantees, and why

    • At most once. An effect is created only if absent, so there is one fx/<n> per n. Each lists only names strictly after the previous last, so no two effects share a command.
    • An acked command is never skipped. Its PUT landed before its writer read a watermark below its name. A producer that lists past that name read a watermark ≥ the name, so it read after the writer did, so its LIST started after the PUT landed and includes it. last only moves over names a LIST returned.
    • Late PUTs are harmless. A command that lands at or below an effect's last is never listed again: it is dead. Its writer cannot have been acked: the watermark it reads is ≥ that last.
    • Every acked command eventually runs, as long as the watermark keeps rising and one producer keeps working.
    • Producers may crash anywhere. State lives only in the bucket. Racing producers waste work; the conditional effect PUT keeps one result.

    Unknown means unknown. A writer that sees name ≤ watermark may still run, if its PUT landed before a LIST passed its name. Wait for the outcome; make the command idempotent if retrying matters.

    What it assumes about S3

    • Conditional PUTs on one key are atomic: of racing If-None-Match: * PUTs one wins; If-Match loses no update.
    • Reads and writes of one key are linearizable: once any client has read a value, no later read returns an older one. AWS documents read-after-write consistency; linearizability while a write is in flight is assumed.
    • A LIST started after a PUT returned includes that key. LIST returns keys in byte order.
